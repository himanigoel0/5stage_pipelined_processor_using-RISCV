# Static Branch Predictor using BTFNT (Backward Taken Forward Not Taken)

## Objective

The objective of this assignment is to design and implement a Static Branch Predictor for a 5-stage RV32I pipelined processor.

Branch instructions introduce control hazards because the processor does not immediately know whether a branch will be taken or not taken. This uncertainty can lead to incorrect instruction fetching and performance degradation.

The purpose of branch prediction is to reduce the control hazard penalty by predicting branch outcomes before the actual branch decision is resolved.

---

# Introduction

In a pipelined processor, multiple instructions execute simultaneously in different pipeline stages.

When a branch instruction enters the pipeline, the processor must determine whether:

* The branch will be taken.
* The branch will not be taken.

However, the actual branch decision is typically known only in later pipeline stages.

Without branch prediction:

* The pipeline may stall.
* Wrong instructions may be fetched.
* Overall performance decreases.

Branch prediction allows the processor to make an early guess regarding branch behavior.

---

# Types of Branch Prediction

Branch prediction techniques are generally classified into two categories:

## 1. Static Branch Prediction

The prediction decision remains fixed and does not depend on execution history.

Examples:

* Always Taken
* Always Not Taken
* Backward Taken Forward Not Taken (BTFNT)

Advantages:

* Simple hardware
* Low area overhead
* Fast implementation

---

## 2. Dynamic Branch Prediction

Prediction depends on previously observed branch behavior.

Examples:

* 1-Bit Predictor
* 2-Bit Saturating Counter Predictor
* Branch History Table (BHT)
* Tournament Predictor

Advantages:

* Higher prediction accuracy

Disadvantages:

* Additional hardware complexity
* More storage requirements

---

# Implemented Predictor

The implemented predictor follows the:

## BTFNT Strategy

Backward Taken Forward Not Taken

This strategy is based on common program behavior.

### Observation

Most loops generate backward branches.

Example:

```assembly
LOOP:
    ADDI x1, x1, -1
    BNE  x1, x0, LOOP
```

The branch target is located earlier in memory.

Therefore:

```text
Offset < 0
```

Such branches are usually taken repeatedly during loop execution.

---

Forward branches are generally used for:

* Conditional execution
* If-Else Statements
* Error Handling

These branches are less likely to be taken.

Therefore:

```text
Offset > 0
```

is predicted as Not Taken.

---

# Prediction Policy

The predictor follows the following rules:

| Branch Offset          | Prediction |
| ---------------------- | ---------- |
| Negative Offset        | Taken      |
| Positive Offset        | Not Taken  |
| Non-Branch Instruction | Not Taken  |

---

# Hardware Implementation

The branch immediate generated by the Immediate Generator is examined.

The sign bit of the branch offset determines the prediction.

### Decision Logic

```verilog
always @(*) begin

    if(branch) begin

        if(imm[31] == 1'b1)
            predict_taken = 1'b1;

        else
            predict_taken = 1'b0;

    end

    else
        predict_taken = 1'b0;

end
```

---

# Working Principle

Step 1:

Branch instruction is decoded.

Step 2:

Immediate Generator produces branch offset.

Step 3:

The predictor examines the sign bit of the offset.

Step 4:

Prediction is generated.

* Negative Offset → Predict Taken
* Positive Offset → Predict Not Taken

Step 5:

Processor continues fetching instructions based on the prediction.

# Advantages

1. Extremely simple hardware implementation.

2. No branch history storage required.

3. Low power consumption.

4. Fast prediction generation.

5. Effective for loop-intensive programs.

---

# Limitations

1. Cannot learn program behavior dynamically.

2. Lower accuracy compared to dynamic predictors.

3. May mispredict unusual branch patterns.

4. Prediction accuracy depends on program structure.

---

# Applications

Static branch prediction is commonly used in:

* Educational processors
* Small embedded processors
* Resource-constrained systems
* Initial pipeline design studies
